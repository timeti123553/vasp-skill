结构优化

1. 报错：

You have a (more or less) 'small supercell' and for smaller cells |

| it is recommended to use the reciprocal-space projection scheme! |

| The real space optimization is not efficient for small cells and it |

| is also less accurate ... |

| Therefore set LREAL=.FALSE. in the INCAR file

解决：在INCAR中修改LREAL=.FALSE.

2. 报错：

Warning from LATTYP: Monoclinic adjustement (A1->A3, A2->A1, A3->A2)!

Warning from LATTYP: Got some problem with cell dimensions!

Tried to take original basis but could not verify dimensions!

LATTYP: Found a simple monoclinic cell.

解决：晶胞过大，选用原始晶胞

取消对称性，在INCAR中输入一行：ISYM=-1

ZPE(Zero point energy,零点振动能)

3. 报错：

For optimal performance we recommend to setNCORE= 4- approx SQRT(number of cores)

NCORE specifies how many cores store one orbital (NPAR=cpu/NCORE) .This setting cangreatly improve the performance of VASP for DFT.The default,NCORE=1

might be grossly inefficient

on modern multi-core architectures or massively parallel machines .Do your own testing ! ! ! !

Unfortunately you need to use the default for Gw and RPA calculations(for HF NCORE is supported but not extensively tested yet)

解决：

NPAR parallelization over bands

NCORE determines how many cores work on one orbital.

NCORE = total number cores/NPAR. 指NPAR近似等于并行核数的开方

可以依据实际的机器情况及计算问题设置，例如：

NPAR = 4, 6, 8 或者 NCORE = 12

以上给出的是推荐的，但实际值请根据实际测试经验确定，官方给出的建议是：

For optimal performance we recommend to set NCORE= 4 - approx SQRT( number of cores)

小编当时设置的是NCORE=8，就没有报错了

4. 报错：

Your generating k-point grid is not commensurate to the symmetryof the lattice.This can causeslow convergence with respectto k-points for HF type calculations

suggested SoLUTIONS:

) if not already the case,use automatic k-point generation

) shift your grid to Gamma (G) (e.g. required for hex or fcc lattice)

解决：

将KPOINTS文件中 Monkhorst-Pack改为Gamma

不同于文献设置

Gamma和MP在某一方向上产生K点数为偶数时是不同的，这时Gamma会有一个点在Gamma（0,0,0），但MP不会。MP只有当三个方向产生奇数个K点时才会包含Gamma点。

参见手册：[http://cms.mpi.univie.ac.at/vasp ... esh_generation.html](https://zhuanlan.zhihu.com/p/449755288/edit#opennewwindow)

使用对称性时，是否包含Gamma点一般会影响最后不可约K点的数目，从而影响精度。

参见手册 [http://cms.mpi.univie.ac.at/vasp ... aring.html#im-smear](https://zhuanlan.zhihu.com/p/449755288/edit#opennewwindow)

不过关闭对称性时，都是沿着X方向砍一半K点，差别应该不会大。

使用MP时，大多还是用奇数个K点，因为这样包含Gamma点，

5. 报错：

No initial positions read in

解决：

对POSCAR选择性优化时，需在元素数字和Direct中间一行加Selective dynamics, 并且优化的原子后要加T T T，固定的原子加F F F，每个原子后都必须补齐

6. 报错：

Error EDDDAV: Call to ZHEGV failed. Returncode = 84 2 160

WARNING: Sub-Space-Matrix is not hermitian in DAV 43

Error EDDDAV: Call to ZHEGV failed. Returncode = 9 1 10

解决：（1）将INCAR精度调低，重新运行，补充一点，可能是ISPIN和MAGMOM的问题：这篇博文提到[http://blog.wangruixing.cn/2019/05/01/scf/](http://blog.wangruixing.cn/2019/05/01/scf/)

（2）检查初始磁矩设置(MAGMOM)是否合理，对于无磁性体系给予默认的磁矩或者高初始磁矩可能会出现Error EDDDAV: Call to ZHEGV failed报错。特殊的磁性排列的体系(AFM, FM)，MAGMOM要设置合理。

7. 报错：

VERY BAD NEWS! internal error in subroutine PRICEL (probably precision problem, try to change SYMPREC in INCAR ?):

Sorry, number of cells and number of vectors did not agree. 3

解决：是SYMPREC问题：默认的0.00001太高,0.001可行

更改了一下，确实可以用于是将SYMPREC＝0.001 添加到INCAR最后一行

结果确认可行。

10. 问题：

在计算物质TOTEN Energy（能量，eV）时，能量相差10+个eV.

原因：

1） 是否考虑了范德华力

LVDW=.TRUE. #考虑范德华力

2） 检查POTCAR元素顺序是否和POSCAR一致，不一致的情况也会相差10+个eV.
