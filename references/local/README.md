# references/local/ —— 让 vasp.skill「记住你」的地方

这里存放**跨会话还用得上的本地事实**，目的是让你下次不必重复交代同样的背景。

它不是自动记忆，而是**一个固定位置 + 一条固定规矩**：
每次动手前先读，学到稳定事实就回写。内容全是你能看、能改、能删的 markdown。

## 和 `references/articles/` 的区别

| | `references/articles/` | `references/local/` |
| --- | --- | --- |
| 来源 | 外部文章、教程、别人的报错记录 | **你自己**的环境与习惯 |
| 内容 | 通用的 VASP 知识 | 绑定你这台机器、你这个课题组的事实 |
| 换机器/换组 | 仍然有效 | **需要重写** |

## 两个文件

| 文件 | 放什么 |
| --- | --- |
| [`machine.md`](machine.md) | 本机环境：VASP 可执行文件、提交方式、并行规模、POTCAR 库路径与 `map.json` 位置 |
| [`conventions.md`](conventions.md) | 参数惯例：默认 `ENCUT`、k 点密度、泛函/加 U 口径、二维/磁性等分体系的固定做法、目录命名习惯 |

## 规矩（`SKILL.md` 里也写了）

- **读**：接到任务（生成输入文件、诊断报错、出图）时先看这两个文件。不存在、为空、或某项没写，就跳过并**照常询问**——**不要凭空编造本机信息**。读到了就直接沿用。
- **写**：学到一条「下次还用得上」的稳定事实时追加进去，并**告诉用户写了什么、写在哪**，方便核对。
- **不写**：一次性的计算结果、临时路径、本次会话里已经明确的事情。
- **别滥写**：不是每轮对话都要留下痕迹。只有确实是稳定事实、且下次确实会用上时才写。

## 分享前请清空本目录

这里的内容只对**你的机器**有意义，而且可能含内网路径、队列名、账号相关的命名习惯。
把 skill 传到 GitHub 或给别人之前，请清空 `references/local/`（保留本 README 即可），
并建议把 `references/local/*.md`（本 README 除外）加进 `.gitignore`。

## 模板写法

两个文件里都给了字段模板。**用不到的行留空或删掉，不要猜着填**——
写错的本机信息比空白更有害，因为它会被后续会话当成事实直接沿用。
